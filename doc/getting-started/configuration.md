# Configuration

## Environment File

.env is local and ignored by Git:

~~~text
X_MONITORED_HANDLE=thsottiaux
TELEGRAM_BOT_TOKEN=replace-with-bot-token
TELEGRAM_CHAT_ID=replace-with-private-chat-id
~~~

X_MONITORED_HANDLE accepts @handle or handle and overrides the YAML account. This is the preferred way to use the same repository with another monitored account.

## YAML Files

Copy the tracked examples to local files:

- config.yaml controls runtime, provider, polling, notification, and gaming behavior.
- preferences.yaml controls interests, ignored content, author context, competitor glossary, and interpretation rules.

The examples contain the current Codex-focused profile. The monitored author context identifies Tibo as an OpenAI employee and treats the monitored text as primary evidence when it is a reply or repost.

## Important Settings

| Setting | Default | Meaning |
|---|---:|---|
| fetcher.poll_min_seconds | 10 | Lower normal polling bound |
| fetcher.poll_max_seconds | 90 | Upper normal polling bound |
| fetcher.bootstrap_mode | baseline | Avoid historical notifications on first startup |
| notification.min_importance | 6 | Final delivery threshold |
| llm.model | qwen3:4b | Local text classifier |
| runtime.retry_base_seconds | 30 | Initial retry delay |
| gaming.check_interval_seconds | 3 | Game-process check interval |
| gaming.restart_delay_seconds | 30 | Cooldown before resuming after gaming |

## Game Process List

The default triggers are:

~~~yaml
gaming:
  processes:
    - VALORANT-Win64-Shipping.exe
    - VALORANT.exe
    - cs2.exe
    - LoveChoice.exe
~~~

Add executable names to the local config.yaml when another game should pause monitoring. General launchers and development tools are deliberately not triggers.

## Preferences

Tags are generated by the model rather than selected from a fixed vocabulary. The model receives the interest list, ignore guidance, author context, competitor glossary, tone/stance instructions, and bounded tag-affinity learning from previous ratings.
