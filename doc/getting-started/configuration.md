# Configuration

XListener combines environment variables, `config.yaml`, and `preferences.yaml`. The repository includes examples for both YAML files and `.env`; copy them before editing.

## Secrets and Environment Variables

Keep secrets in `.env`, which is local and ignored by Git:

```dotenv
# Optional: overrides account.handle in config.yaml
X_MONITORED_HANDLE=example_handle

TELEGRAM_BOT_TOKEN=replace-with-your-bot-token
TELEGRAM_CHAT_ID=replace-with-your-private-chat-id
```

X credentials are intentionally separate from `.env`. Save them with `scripts/store_x_credentials.py`; on Windows, `keyring` uses Windows Credential Manager.

Never put passwords, browser session files, bot tokens, or chat IDs in tracked YAML files, source code, issues, or screenshots.

## Runtime Configuration

`config.yaml` controls account selection, polling, model access, delivery, retention, runtime paths, and gaming behavior. The following settings are the usual starting points:

| Setting | Default | Purpose |
|---|---:|---|
| `account.handle` | `thsottiaux` | Account to monitor when `X_MONITORED_HANDLE` is unset. |
| `fetcher.poll_min_seconds` | `10` | Minimum delay between polls. |
| `fetcher.poll_max_seconds` | `90` | Maximum delay between polls. |
| `fetcher.max_posts_per_poll` | `20` | Bounded number of recent posts fetched per cycle. |
| `fetcher.bootstrap_mode` | `baseline` | Sets the current cursor on first run without notifying old posts. |
| `notification.min_importance` | `6` | Minimum model importance score required for delivery. |
| `llm.model` | `qwen3:8b` | Local Ollama text model. |
| `runtime.retry_base_seconds` | `30` | Initial retry delay for durable failures. |
| `runtime.retry_max_seconds` | `1800` | Maximum retry delay. |
| `learning.processed_id_retention_days` | `30` | Retention period for deduplication checkpoints. |

Paths accept environment-variable expansion. By default, Windows runtime data is written under `%LOCALAPPDATA%\XListener\`; see [Runtime and data](../engineering/runtime-and-data.md).

## Bootstrap Modes

On a first run, the application has no cursor. Choose one of these values for `fetcher.bootstrap_mode`:

| Value | Behavior |
|---|---|
| `baseline` | Record the newest fetched post as the starting cursor; do not process older posts. This is the recommended default. |
| `process_latest` | Process only the newest fetched post. |
| Any other value | Process the fetched window. Use only when intentional. |

## Preferences

`preferences.yaml` is the local policy given to the classifier. It supports:

- `interests`: topics and priorities that should be surfaced;
- `ignore`: content that should usually be suppressed;
- `author_context`: background for the monitored account, including `product_aliases` such as Sol, Terra, and Luna and `official_handles` for organization accounts;
- `entity_context`: organizations, aliases, products, and relationships that clarify related posts;
- `interpretation_rules`: guidance for replies, reposts, ambiguity, and attribution.

Tags are generated by the model rather than selected from a fixed vocabulary. Ratings influence a bounded local tag-affinity profile; they do not rewrite historic classifications.

When you monitor a different account, update `author_context.handle` to match it. If it does not match the configured monitored handle, XListener deliberately replaces the account-specific context with a neutral fallback.

## Gaming Pause Settings

The Windows supervisor can pause monitoring while selected games are running:

```yaml
gaming:
  enabled: true
  processes:
    - VALORANT-Win64-Shipping.exe
    - VALORANT.exe
    - cs2.exe
  restart_delay_seconds: 30
  unload_ollama_models: true
```

List executable names, not launcher names. When a configured process is detected, the supervisor stops the daemon and can ask Ollama to unload the configured text and vision models. It restarts the daemon after the configured cooldown once the process is gone.
